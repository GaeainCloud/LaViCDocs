# Physics Audit Skill (物理规则约束审查)

## 技能描述
本技能旨在对仿真场景中的实体进行严格的物理规则约束审查，确保仿真结果符合物理世界的公理与逻辑。审查范围覆盖运动学、环境空间及资源能量三大维度。

## 审查内容

### 1.1 physics_audit (物理规则约束)

#### 1.1.1 L1: 运动学一致性 (Kinematics)
确保实体像“物体”一样运动，而不是像光标一样闪烁。

*   **极速限制 (Maximum Speed Cap)**
    *   检查实体在任何一段位移中的速度是否超过了其物理设计极限。
    *   例如：驱逐舰不能跑出快艇的速度，螺旋桨飞机不能突破音障。
    *   目的：防止参数配置错误导致“超人实体”出现的最基本防线。

*   **失速与最小速度阈值 (Stall Speed Threshold)**
    *   针对固定翼飞机（非直升机/垂直起降战机），检查其飞行速度是否低于产生升力所需的最小速度。
    *   逻辑：如果飞机在空中（且非起降阶段）的速度接近于零或低于失速速度，物理引擎应判定其失去升力并坠毁，而不是悬停在空中。

*   **时空连续性检测 (Temporal Continuity)**
    *   检查实体在极短时间内的位置变化量。
    *   逻辑：物理世界中不存在“瞬移”。如果一个物体在 0.1 秒内出现在了 100 公里外，或者时间没有流逝但位置发生了改变，这属于严重的时空逻辑错误。

*   **机动过载限制 (G-Force / Maneuverability)**
    *   检查实体在进行急转弯或剧烈机动时的离心加速度。
    *   逻辑：无论是机械结构（如机翼折断）还是生物生理（如飞行员昏迷），都存在承受极限。如果轨迹显示出瞬间直角转弯或违背惯性的机动，应判定为物理违规。

#### 1.1.2 L2: 环境与空间限制 (Environment & Space)
确保实体在正确的介质中生存，且不违背几何公理。

*   **介质排他性 (Domain Validity)**
    *   检查实体是否处于其物理属性允许的介质中。
    *   例如：水面舰艇的高度必须紧贴海平面，潜艇不能在陆地坐标航行，地面车辆不能在深海区域行驶。
    *   目的：防止“陆地行舟”或“潜艇上天”等低级视觉错误的机制。

*   **实用升限与最大潜深 (Service Ceiling & Max Depth)**
    *   检查空中和水下实体在垂直轴（Z轴）上的极限。
    *   逻辑：飞机不能飞得比大气稀薄极限更高，潜艇不能潜得比耐压壳体极限更深。这限制了实体的垂直活动空间，防止其进入物理上无法生存的区域。

*   **地形避障与防撞 (Terrain Collision / CFIT)**
    *   检查实体的轨迹是否与数字高程模型（地形数据）发生交集。
    *   逻辑：在三维空间中，任何时刻实体的海拔高度如果低于该坐标点的地面/海床高度，即判定为撞山或触礁，而非穿模通过。

*   **地球曲率视线遮挡 (Radar Horizon / Line of Sight)**
    *   基于地球是球体的物理事实，检查观察者与目标之间是否存在视线遮挡。
    *   逻辑：电磁波和光线沿直线传播（忽略大气波导），如果目标位于地平线以下，物理法则规定其不可被直接探测或锁定。

#### 1.1.3 L3: 资源与能量守恒 (Resources)
确保实体的行动有代价，拒绝无限续航。

*   **弹药硬约束 (Hard Ammo Limit)**
    *   统计实体在整个仿真过程中消耗的弹药总量，并与其携带能力进行对比。
    *   逻辑：物理实体不能发射超过其载弹舱或挂架数量的武器，一旦耗尽，必须经过补给动作或冷却时间才能再次发射。

*   **最大物理航程 (Max Ferry Range)**
    *   基于燃料或电池容量，检查实体的累计移动距离。
    *   逻辑：无论实体如何机动，其总行程不能超过满油状态下的最大转场航程。这是防止实体在没有空中加油或补给的情况下执行超长距离任务的约束。

*   **最大留空/作战时间 (Max Endurance)**
    *   针对长时间盘旋或低速作业的实体（如无人机、预警机、潜艇），检查其任务总时长。
    *   逻辑：限制它们的往往不是距离而是能源消耗的时间速率，超过设计续航时间未返航即判定为能源耗尽坠毁。

*   **挂载互斥与载重限制 (Payload Mutex & Weight)**
    *   检查实体的武器挂载配置是否符合物理和气动限制。
    *   逻辑：一个挂点不能同时挂载两种武器，且所有挂载物的总重量加上机身燃油，不能超过载具的最大起飞重量（MTOW），否则无法起飞或机动性严重受损。

### 1.2 因果链条 (Causal Chain)

#### 1.2.1 感知-决策-执行链 (Perception-Decision-Action Chain)
*   **本质**：信息的因果。它定义了智能体获取外部情报与产生外部动作的先后顺序。
*   **详细说明**：在仿真中，Agent 必须是“有感而发”。“知”是“行”的输入参数。例如：A 在 T1 时刻发射导弹攻击 B，但在整个系统的时间序列 [T0, T1] 中，没有任何传感器（无论是 A 自己的，还是体系内共享的）上报过关于 B 的位置和属性，那么 A 的攻击就是“无源之水”。在LaViC的simulation.json中，fldmds数组代表了场域、感知域或类似传感器的能力，是实体感知的“眼睛”。如果是仿真中两个感知域发生“碰撞”，将会使用OODA的方式得到信息，OODA将通过GaeaScript脚本的方式，通过调用引擎去执行或者去触发动作指令（action）。

#### 1.2.2 指令-反馈闭环 (Command-Response Loop)
*   **本质**：权力的因果。它定义了层级化组织中，动作授权的来源与闭环。
*   **详细说明**：仿真系统通常包含指挥官、平台、武器等多个层级。非自主行为（如战略机动、大规模开火）必须能回溯到一个上级下达的 Command 事件。同时，一个完整的逻辑闭环还应包含反馈：如果指令下达了，Agent 执行了，必须产生一个 StatusReport 或结果反馈。如果没有指令却动了，是“兵变”；如果有了指令没反馈，是“通信黑洞”。

#### 1.2.3 状态转换的连续性 (State Transition Continuity)
*   **本质**：过程的因果。它定义了实体生命周期中物理过程的不可跨越性。
*   **详细说明**：实体的行为是由有限状态机（FSM）驱动的。例如，导弹的状态机路径必须是：发射(Launched) -> 飞行(In-flight) -> 命中/失控(Terminal)。如果审计发现一个实体在上一帧还没有发射，下一帧直接变成了 Terminal，虽然物理上可能就是两个坐标点的变化，但在逻辑链上这是非法跳变，会导致后端数据统计和毁伤评估出现致命错误。

#### 1.2.4 物理触发的逻辑一致性 (Trigger-Effect Consistency)
*   **本质**：环境的因果。它定义了外部物理刺激与内部逻辑响应的强制关联。
*   **详细说明**：仿真世界必须对物理干扰有“应激反应”。例如，当系统产生了一个 Jamming（干扰）物理场，覆盖了 Agent A，那么 A 的内部逻辑状态中 Signal-to-Noise Ratio（信噪比）必须下降，进而触发 DetectionLoss（目标丢失）逻辑。如果环境变了，Agent 却纹丝不动，逻辑一致性就打破了。

## 输出要求
审查完成后，必须生成一份详细的 Markdown 格式报告文件（如 `physics_check_report.md`），列出所有违规项及相关统计数据。
